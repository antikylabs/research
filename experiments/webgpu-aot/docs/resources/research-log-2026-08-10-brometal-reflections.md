# BroMetal Roughness-Reflection Experiment

## Question

After BroMetal's particle buffer became exact, the image still scattered many sharp red particle reflections across the walls and foreground floor. Three.js instead reconstructs one raw mirror trace into a five-level blur pyramid and selects a fractional level from the receiving material's squared roughness.

BroMetal had no equivalent reconstruction stage. Its single reflection shader traced, applied several local confidence heuristics, added the result directly to the scene HDR, and sent that full-resolution texture to bloom and presentation. This experiment separated those responsibilities while keeping accepted particles, analytic lights, cascaded sun, AO, bloom settings, exposure, and output transform fixed.

## Native BroMetal graph

BroMetal now independently owns a seven-pass reflection graph:

1. one full-resolution `rgba16float` raw SSR trace;
2. one exact mip-0 copy and four 7×7 box reconstructions, each sampling the immutable raw trace directly with spread 1–4;
3. one full-resolution selector sampling the five-mip pyramid at `clamp(roughness² × 4, 0, 4)` and adding the selected reflection to scene HDR.

The reconstruction is not a generic shared renderer and does not import Three.js or another demo. It is generated by BroMetal's own AOT compiler into two additional static WGSL modules. At the heavy 2560×1440 profile, the raw trace, five-level pyramid, and selected reflected scene occupy 98,265,600 bytes and add six fullscreen passes relative to the former single-pass path.

## Red-first evidence

The first regressions failed because BroMetal exposed no reflection plan, no reconstruction/selection artifacts, and the raw shader still returned `base + reflection`. The tests now prove:

* exact mip dimensions and spreads at 2560×1440;
* exactly seven reflection passes;
* direct-from-raw 7×7 reconstruction with 49 equal taps;
* fractional roughness-squared selection;
* deterministic generated artifacts for all nine BroMetal modules.

The complete package passed 32 tests, package typecheck, deterministic shader regeneration, and a production build.

## First capture: reconstruction exposed the wrong source

The first candidate capture is `/tmp/brometal-roughness-ssr-1`. It completed with all five demos ready at frame 12, no issues, and report status `PASS`. Similarity improved from the exact-particle control `0.945897` to `0.946416`. Sharp single-pixel reflection noise became smoother, and the display floor cue improved slightly to contrast `0.117116` and ratio `1.432618`.

Human inspection nevertheless rejected the image as final: reconstruction spread a long bright red streak down the left foreground floor. Three.js has no such streak. The correct blur graph had exposed a bad raw hit distribution rather than creating it.

## Raw hit-transfer correction

BroMetal's old accepted-hit transfer multiplied sampled HDR by step confidence, edge fade, an invented metallic range, receiver roughness attenuation, and a Schlick-like factor. That routing strongly favored the wrong floor hits. The raw trace now uses the independently implemented mirror-transfer contract:

```text
planeDistance = dot(hitPosition - surfacePosition, surfaceNormal)
weighted = hitColor × metallic
weighted *= (1 - planeDistance / 100)²
weighted *= (dot(incident, reflected) + 1) / 2
weighted *= min(10 / max(rec709Luminance(weighted), 0.0001), 1)
reflection = weighted × 0.7
```

A pure CPU contract and generated-WGSL assertions were added red-first. The test covers distance attenuation, grazing/metallic response, luminance limiting, and removal of the rejected confidence and roughness heuristics.

## Second capture: polished shape, insufficient raw coverage

The corrected capture is `/tmp/brometal-roughness-ssr-2`. It also completed cleanly with exact particle parity. The false floor streak disappeared completely, as did most of the sharp wall/floor speckle field. From a human-eye polish perspective, this is the strongest BroMetal reflection result in the experiment.

The quantitative result exposes the next missing system rather than declaring full parity:

| Metric | Exact-particle control | Reconstruction only | Corrected transfer |
| --- | ---: | ---: | ---: |
| Final similarity | 0.945897 | 0.946416 | 0.945233 |
| Floor-pool contrast | 0.116158 | 0.117116 | 0.107614 |
| Floor-pool ratio | 1.430995 | 1.432618 | 1.408183 |
| Coherent-row fraction | 0.991561 | 0.987342 | 0.940928 |
| Upper-spill contrast | 0.219102 | 0.219467 | 0.215701 |

The corrected image is darker and contains too little subtle reflected red energy compared with Three.js. This is not a reason to restore the false heuristic transfer or the unfiltered speckles. It means BroMetal's fixed 24-step world-distance marcher, widening radial thickness, missing hit-normal rejection, and lack of crossing refinement do not find the same valid screen-space intersections as Three.js.

## Decision

Retain the roughness reconstruction and physically defined raw-hit transfer as the more polished and source-correct checkpoint, while recording that the aggregate screenshot score regressed by `0.000664` from the exact-particle control. The human-visible false streak and sharp speckles are removed, and the remaining deficit is now localized to trace coverage.

The next bounded BroMetal reflection experiment should change only ray construction and hit geometry: screen-space dominant-axis stepping toward the reference maximum distance, local pixel thickness, hit-normal rejection, and binary refinement. It must hold this transfer, reconstruction pyramid, particles, lights, sunlight, bloom, and presentation fixed. A global reflection gain would raise energy without repairing spatial coverage and is therefore rejected.
